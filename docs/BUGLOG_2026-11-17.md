## 3. Root causes actually verified & fixed (17 Nov, evidence-backed)

1. **`mj_step` was deleted from `PhysicsWorld._step`** — the whole simulation
   never integrated (time stayed 0.0; all physics frozen; no falls/flights/
   collisions could ever occur). Restored `self._prev_qvel[:] = d.qvel` +
   `mujoco.mj_step(self.m, d)` exactly where HEAD had them (verified against
   `git show HEAD:`; live probe: time 0.0 → 0.48 s after 240 steps).
2. **`_step` scoping bug** — the PD loop *and* Newton's-third-law reaction were
   accidentally gated inside `if self._gait_controller is not None`, silently
   skipping reaction physics and PD for box worlds. Restructured; PD
   application is method-level; unknown joints are dropped with an event
   instead of corrupting the step.
3. **Unconditional spawn writes at 3 sites** (`__init__`, `set_state`,
   `setup_finish`) wrote `qpos[aq+3:aq+7] = [1,0,0,0]` — in box worlds that is
   block_01's freejoint pos slot → teleport to (1,0,0) on every world
   construction/checkpoint restore. Now gated: `set_state` does nothing
   (checkpoint fidelity); `__init__`/`setup_finish` call a shared
   `_humanoid_spawn_reset()` that resets ONLY the agent's own limb hinges and
   is a no-op for box worlds.
4. **`total_mass()` returned 0 for the humanoid** (massless container body ->
   ZeroDivisionError in `move()`; zero traction force). Now returns subtree
   mass; traction uses `total_mass()`; carried-mass displays clamp ≥ 0.
5. **`world.move(…, stop=False)` would raise / hang** — test-driving with the
   legacy force path hit `distance / total_mass() = 0`. Fixed by 4; the
   `move()` blocked-raise is caught in the walking test (boundary stop).
6. **Humanoid rig floated 0.8 m above the ground** — the asset torso block
   (`pos="0 0 1.15"`, asset ground at 0) was nested under the agent body whose
   origin sits at `hh+0.002` (0.802 m), so every spawn began with a 0.8 m
   free-fall (the QACC blow-ups at t≈0.44 s). Fixed by offsetting the torso to
   `pos="0 0 0.348"` at integration time (asserts if the asset anchor moves),
   so feet land at the agent root height and spawn z = 0.01 m.
7. **The humanoid's `<default>` joint contract was dropped** — `spec.py`
   copied only the humanoid `<asset>` block; the `<default>` block (documented
   rig contract: `damping="1.5" limited="true" range="-90 90"` on every joint)
   was never included, so every hinge compiled **unlimited and undamped** —
   the ankle could spin 9.78 rad and slam the solver (qacc → 5e9) instead of
   standing. Fixed by also extracting `<default>`.
8. **Frictionless limb pairing had the wrong contact priority** — contact
   parameters come from the geom with the LOWER priority; the floor compiles at
   priority 0, so `priority="1"` limb geoms never received the frictionless
   pairing on foot-ground contacts. Now `priority="-1"` (cfg switch
   `agent_body.limb_friction_engine: true/false`; false = asset original kept
   as comparison baseline until the new config passes standing + walking +
   recovery).
9. **`tests/test_locomotion.py:73` np.linalg-module bug** — assert compared
   against the module; covered by the speed-scaling fix in the same file
   (test 3 asserts the *measured* velocity now).
10. **Recovered `playground/locomotion.py`** from the previous session's log
    (the clean rewrite that failed to write, minus its `move(…, 1e9)` bug →
    `target_vel` traction drive + traction ramp; PD-target-only honesty
    contract documented in its module docstring).

## 7. Walk redesign — rig corrections + contact-driven gait (Nov 17, night)

The 8-case walking isolation matrix (orig + gentle params) had **zero passing
cases**: orig params folded at ~3 s (slip-catch: ankle toe-down under drag),
gentle params blew the solver up (qacc 1e6-1e9). Root causes, each fixed with
in-repo evidence:

1. **move() stop=False regression** — the working tree reinterpreted `distance`
   as a *force* under stop=False (accel = force/mass), so the box crawled and
   the 0.5 s / 0.01 m blocking check fired "unknown obstacle". Restored HEAD
   semantics (v_t = speed, cruise continues after an unblocked finish). Tracked
   test test_hve.py::test_running_throw_carries_further green again.
2. **Humanoid move()** — root traction is disabled for humanoids (the traction
   couple folds the legs), so move() now routes the humanoid through the gait
   controller (walk mode at the requested speed/heading) inside the same
   progress/blocked/timeout loop. Box agents keep the traction pathway.
3. **Rig faced the wrong way for its hinges** — the asset (spine lean about X,
   hips/shoulders laterally offset along X) implies the figure FACES +Y, but
   every limb hinge was a Y-hinge, so both legs swept in ONE sagittal plane and
   the feet collided mid-stride (qacc 6.9e9). All sagittal limb hinges re-axised
   to X (hips/knees/ankles/shoulders/elbows/head pitch), head roll swapped,
   feet re-long-axis'd to Y. Positive hip = leg forward; heel-back flexion is
   NEGATIVE knee.
4. **No yaw compliance in the leg chain** — the first walking attempt dumped a
   ramped -90 deg waist yaw into a chain with only X-hinges: the planted feet
   (mu_lateral 0.9) got scrubbed sideways through an infinitely stiff chain and
   the solver blasted the figure apart (feet driven INTO the torso, qacc 1e8).
   Added ankle yaw dofs (`left/right_foot_yaw` Z-hinges, full +/-180 deg, damped
   2.0; the foot became its own body) so planted feet twist in place against the
   near-zero torsional friction while the figure turns.
5. **waist_yaw + pelvis mass** — heading needs a rotational root dof: added
   `waist_yaw` (Z-hinge at the torso, +/-180 deg, damping 2.0). With the torso
   articulated the agent container lost its welded mass; a near-massless token
   inertia collapsed the waist dof inertia (qacc 1e10). The container now
   carries pelvis-class mass (10 kg, inertia 1.0/1.2/1.2-ish) and
   total_mass() reads body_subtreemass (identical value for box worlds).
6. **Ankle damp above the step-impulse limit** — the free swing foot's inertia
   about the ankle is ~0.003 kg m^2, so kd=3 exceeds kd<=I/dt=1.5 at swing
   speeds: the damping torque overshoots each step and the ankle spins to NaN.
   ankle kd 1.0 (swing), stiff gains ONLY while planted.
7. **Gait pattern regenerated** (playground/locomotion.py): hip = a*cos(2*pi*phi)
   antiphase (the stance sweep IS the drive), swing-knee clearance bump only
   (heel-back), ankle = -(hip+knee) level rule, sweep capped at 0.24 rad (keeps
   the CoM ground line inside the sole span so the ankle never fights an
   unwinnable tipping moment), knee/ankle stiffness switched on ACTUAL foot
   contact with 0.06 s hysteresis (stiff planted: knee 400, ankle 600/kd 6;
   soft airborne: knee 50/5, ankle 25/1), hip gains phase-weighted. Heading
   maps to waist = heading - 90 deg (the figure walks toward its local +Y);
   move()'s heading request is degrees only (the old <=2pi-heuristics turned a
   3 deg step into a 172 deg turn).
8. **First stable contact-driven walk** (asset friction): 8 s, z holds
   0.797-0.801 (no sag, no collapse), qacc <= 3.4e3, disp 0.60 m. Heading 90
   produces velocity angle 92 deg (within the +/-30 deg acceptance).

Status after the redesign: standing matrix unchanged-green on the new rig
